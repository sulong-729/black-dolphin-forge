# Acceptance boundaries

A capability is usable only when its live registry schema, owner/session and version preconditions are satisfied. The source reports preserve scoped PASS separately from NOT_RUN and do not turn unavailable capabilities into simulated successes.

P8 delivers portable packaging/upgrade rollback, explicit user-service plans/commands, bounded retention tools, reproducible synthetic measurements and a bundled AI skill. Persistent OS registration/login/reboot/sleep-wake and Windows execution remain unqualified. Native build/deploy/profiler, broad mutations and runtime actions from earlier phases retain their exclusions.

Context target: median token reduction >=70% on the fixed five-task synthetic dataset. Warm target: p95<=300ms for cached in-process graph operations at5000 nodes. Idle sample budget: <=1% of one core and <=192MiB RSS for a fresh daemon with no projects/sessions/jobs, over a2-second sample. Actual results are in the P8 report; these targets are not production-game guarantees. All findings/warnings and semantic task answers must survive compaction.

Portable bundle qualification checks fresh paths with spaces, exact manifest/hash boundaries, the installed launcher, authenticated daemon start/query/stop and expected Editor/worker/skill assets. No production game is used as a writable fixture. Package provenance is checksummed but unsigned, and Node itself is a separate dependency. A release/push/public install remains an explicit user action.

Preferred workflow is AI -> kit -> Cocos. Direct access remains allowed when necessary and authorized; log the fallback reason and recapture stale state. The kit does not promise to constrain an AI that already has unrestricted filesystem/shell permissions.
